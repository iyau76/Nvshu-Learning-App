# 女书学习与研究平台：第二代开发计划

更新：2026-11-02。当前维护基线：合并后的 PR #3。本文件是未来实施计划；除“已完成”事项外，均未宣称已经开发。技术选型、交付顺序和体验设计是本轮提出的执行方案。

## 1. 产品要让人完成什么

打开手机，可以继续昨天的学习；在一道题中遇到一个女书字，能查它的读音与对应表达；打开文献，可以逐行读、逐句听，查看具体写法和人物；研究者能够回到原页、录音时刻和完整上下文，比较不同释读与观点。

第二代产品同时服务三种使用方式：日常学习、文字与文献阅读、资料整理与研究。它们共用人物、字符、作品和出处，新增一条经校订的释读，就能进入查字、阅读、检索与练习。

用户已明确的长期要求：

- 女书知识与女书文字本身都属于学习范围。文字学习要回答：怎么读、对应哪些汉字或音节、有哪些异体、句中是什么意思、谁使用过、出现在哪些原始文献中。
- 拥有《中国女书合集》，希望未来借助 AI 降低数千页的人工标注成本。本轮不启动全书处理。
- 可以采用全栈开发，旧 Python/Kivy 技术栈不再限定产品形态。
- **原始文字材料不能动，不能改成防御性文字。** 新注释、版本、译文和练习与原文分开保存；原文的表达、观点和语气完整保留。
- Agent 承担常规工程判断、实现、运行和修复，让用户集中处理内容判断、产品取舍及实质性验收。

本计划继承历史开发对话、当前仓库和用户提供的 `artifacts/nextsteps.md`。后者的展览、声音、人物、地图、研究、文创等方向进入下列路线；模块名称和技术组合是可以由原型修正的方案。

## 4. 六个决定产品辨识度的体验

### 一个字的使用记录

输入汉字、音节、女书字符，或圈选手稿中的字，打开同一个字页。先呈现读音、对应表达和例句，再展开不同写法、使用者及出处。点击某个写法，原文页滚动并定位到实际字迹。尚未映射到 Unicode 的字图也有稳定标识，可以检索和讨论。

### 听着读一页女书

原页、女书转写、汉字转写、释义与原始录音联动。播放时高亮所在句，点句子可以循环听；手机上以当前行和声音为中心，电脑上可并排对照整页。个人跟读记录留在学习空间，录音者和资料来源始终可找到。

### 随手摘字

拍照或截取一小块文字，先给字形候选和相似例证。选择候选后进入真实用例，遇到难字可连同上下文存入个人摘字本；研究者校订后，新的字例可被其他阅读者检索。早期通过图像相似检索实现价值，再逐步提高整行识别能力。

### 从一道题回到田野

答错后，除原有解析外，还能打开相关手册段落、访谈片段、地点和人物，再回到练习。学习路径可以围绕“三朝书”“一次访谈”“一个村落”组织，文字与文化知识在具体材料中相遇。

### 同一篇作品的多种读法

不同手稿、不同吟唱和不同释读可并排对照。相同位置的字形与读音差异可被高亮；阅读者能保存自己的注释。系统记录每种判断由谁、依据什么材料提出，并支持修订。

### 观点比较与策展

从一个研究问题出发，把有上下文的原文、声音与影像放到同一工作区。由此组织人物专题、文化地图或数字展览。既有矛盾图谱的论述完整保留，新增视图帮助读者进入证据与叙事。

## 5. 第一版应当达到的体验水位

第一个对外可用版本包含：完整旧题库、学习与考试、持久错题与成绩、初步间隔复习、离线学习、字音查询、真实材料阅读切片。文字学习从首版就可见。

首页给出“继续学习、查字、读作品”三个主要动作。资料整理工具放到独立工作区。视觉以真实字迹、原页和声音为主角，字体兼顾女书与汉字阅读；阅读器提供竖排与横排对照、字号调整和深浅模式。地图和图谱用于显示具体关系，进入页面时先交代对象及来源。

代表性原型要完成一条贯通体验：**查到一个字 → 查看一条实际字例 → 读相关句子 → 播放已有录音或查看音标 → 做一道关联练习 → 离线重启后保留记录。** 优先选择已具备材料的字例；没有录音的记录显示现有音标，后续补充声音。

## 6. 全栈架构与复用决定

| 层次 | 默认实施路线 | 选择理由与替换条件 |
| --- | --- | --- |
| 主界面 | React + TypeScript + Vite；响应式 Web/PWA | 同一界面服务浏览器和封装客户端，学习逻辑可离线运行 |
| 桌面与 Android | Tauri 2 验证 Windows 安装包和 Android APK，共用 Web 界面 | 早期实测字体、返回、文件、音频与生命周期；Android 关键能力受阻时评估 Capacitor 作为该平台适配层 |
| API | FastAPI + Pydantic；生成 OpenAPI 契约 | Python 继续承担适合它的业务与资料处理，客户端按契约交互 |
| 主数据库 | PostgreSQL + SQLAlchemy/Alembic | 关系、版本和学习事件先有一致的数据模型；图谱视图由这些关系生成 |
| 文件 | S3 兼容对象存储接口，本地开发使用文件后端 | 原图、音视频、派生图分开管理；记录摘要、尺寸、版本和处理过程 |
| 后台处理 | Python worker + Redis/RQ；任务状态写入 PostgreSQL | OCR、转写、索引和音频处理支持队列、断点、重试和取消 |
| 本地数据 | PWA 使用 IndexedDB；原生客户端按需使用 SQLite 适配器 | 共用本地仓储接口和学习事件格式，支持备份、导入导出与恢复 |
| 检索 | 字符/汉字/音标精确查询 + 中文词项/别名索引 + 向量候选与重排 | 中文检索单独验证切词、异体和音标归一化，不依赖默认英文全文检索配置 |
| 研究阅读 | IIIF 对齐的文献结构、图像区域与时间片段标注；阅读器采用成熟深缩放组件 | 原页位置可共享，后续可导出 TEI/IIIF 兼容资料，避免自造封闭文献格式 |
| 学习调度 | 通过适配器使用 FSRS 实现，保存算法与参数版本 | 保留完整练习事件，升级调度器时可回放；实际保持率决定参数调整 |
| 发布 | GitHub Actions + 容器化服务部署 + 独立静态前端 | 每次发布有可追踪产物、下载校验、备份恢复与回退路径 |

上述路线尚未在本项目完成集成验证。Tauri 官方建议静态前端与明确的客户端/API 分工，这支持 Vite 路线；公开介绍与展览可额外预渲染，避免让客户端依赖服务器渲染。[Tauri 前端配置](https://v2.tauri.app/start/frontend/)

IIIF 已提供组织图像、音视频及标注的结构；它解决交换与呈现，项目仍需设计自己的字符、释读和人物关系。[IIIF Presentation 3](https://iiif.io/api/presentation/3.0/)

FSRS 采用封装接口和锁定依赖，先以固定历史用例验证版本行为。当前实现存在版本迁移要求，不能把旧版调用样例直接当新版本接口。[ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs)

建议目录：

```text
apps/web/                  学习、字库、阅读器、研究工作区
apps/native/               Windows / Android 平台适配
services/api/              数据、用户、同步、检索 API
services/worker/           OCR / 音频 / 索引任务
packages/domain/           抽题、计分、学习事件及客户端规则
packages/contracts/        生成的 API 类型和共享数据规范
data/seed/                 经核对的公开种子数据与原题库快照
data/manifests/            资料清单与版本，体积大的原件放对象存储
infra/                     本地启动、部署和备份恢复
docs/                      路线、数据说明、运行手册
```

原 Kivy 根目录在迁移期间保持可构建。完成第二代稳定发布后，再单独整理第一代历史目录。

## 7. 数据设计：让五个问题都能被回答

| 对象 | 关键关系与保留信息 |
| --- | --- |
| 字符 Character | 稳定内部 ID；Unicode 可选；别名和不同字符表的对应关系 |
| 字形 Glyph | 原始图像/裁片、形态描述、字形关联；一个字符可有多种写法 |
| 字例 Occurrence | 某卷、某页、某栏/行中的一次出现；原图坐标、上下文及阅读顺序 |
| 字属与异体判断 | 某个字例/字形属于哪个字符、两种写法是否为异体；保存提出者、依据、状态和版本，容纳不同判断 |
| 片段与对齐 Segment/Alignment | 有序的原文、音节、汉字转写、释义片段及多对多关联；支持一个字对应多个音节、跨字释义、缺文和音频时间片段 |
| 读音 Reading | 音标原文、音标体系、声调、方言/地点、记录者与来源；不同记录可并存 |
| 释读 Interpretation | 对某个字例/句子的汉字转写、释义、提出者、来源和版本；与字形判断分开 |
| 作品与版本 | 作品、手稿/印本、卷册、页序和书内页码分别建模；复印与转载不算新的原始作品 |
| 人物与参与 | 书写、吟唱、收藏、传授、访谈、释读等角色；关系可附时间及材料依据 |
| 音视频片段 | 文件与时间区间、说话/吟唱者、对应行句；原录音与处理后版本分开 |
| 注释与研究判断 | 指向具体页区、文本范围或时间片段；保留作者、修订和分歧 |
| 学习题与版本 | 题干/解析原文、选项池、关联知识点与材料、题型规则及不可变版本号 |
| 学习事件 | 用户、题目版本、呈现选项、选择、结果、时间、设备和事件 ID |
| 任务与派生物 | 输入摘要、模型/参数版本、任务状态、输出、耗时/费用及复核结果 |

坐标采用原图坐标系，裁剪、旋转、缩放记录变换；PDF 的第几页和书内印刷页码都保存。修订转写后，既有引用仍指向其原版本，界面可提示更新内容。

字例关系支持多对多，字属与异体关系作为可追溯的判断保存，不用一个不可变外键提前裁定所有归属。来源的文字与模型推测有明确记录类型。原题库首次迁移逐字比对，题目身份由稳定 ID 表示，调整排序后学习进度仍正确。

关系数据库先承担上述结构。人物关系图、字形网络和文献引用图是它的不同视图；出现真实查询瓶颈后，再决定是否引入专用图数据库。

### M1：第一轮就验证产品的核心关系

完成 monorepo、启动脚本、数据库迁移与内容导入工具。导入时生成稳定 ID 和版本，旧题库作为只读源快照保存。建立字音表与原图的来源清单，保留历史音标写法。

前端做三个相连的页面：学习、查字、材料阅读。N03 阶段先人工整理一份来源完整的实际原页、字例与句子释读作为种子数据，并覆盖一处多对多对齐或不同释读；阅读器据此开发。后台再支持登记资料、标注字例和关联释读，前端随即能检索到。支持键盘操作、手机触摸、女书补充平面字符的正确保存和显示。

同轮做 Tauri 平台验证：实际加载字体、录音/播放、文件选择、应用切后台再返回、Android 返回键。用这些结果确定原生适配层，保持 Web 版本独立可用。

### M2：把已有学习设计全部兑现

旧学习规则完整继承：单选多表述、随机干扰项、多选抽取 2–3 个正确项、70%/30%抽题、连对两次、章节进度、上下题回看、答后原解析、继续学习和复盘。

考试包括章节卷、综合卷、自选范围。标准综合卷保持 20 单选 × 3 分 + 10 多选 × 4 分；双选漏选得 2 分，三选中 1 项得 1 分、中 2 项得 3 分，错选 0 分；每题一次机会，先单后多。交卷后展示原始分、分项分数和错题回看。

现有“非遗与田野”仅有 8 道多选题。章节题量不足时生成短卷，沿用单题规则并显示“得分/实际满分”和百分比，成绩与标准综合卷分别统计；题量充足后可出标准卷。限时模式作为可选练习，支持中断恢复。

错题本保存每次实际呈现的选项、所选答案及当时题目版本。复习同时提供旧式章节回顾和到期复习。选择题表现与主动回忆难度分开记录，避免把猜对当成稳定记忆。

成就围绕有意义的学习行为：完成章节、完成综合测验、连续复习、读完一篇作品、辨认不同字形、整理一条有依据的字例。成长页面可以展示“我已能读的作品片段”，逐渐将分数与阅读能力联系起来。

旧进度迁移保存实际存在的连续正确次数，包括仅答对一次的状态，不编造答题时间和复习历史。导入包携带旧题库版本、章节/题型/索引映射、进度和设置；新端先预览导入结果，再做幂等写入并保留可回退的导入记录。

Android 先为第一代补一个进度导出入口，通过沿用原签名的维护包交付；用户可以导出文件并在第二代或 Web 中导入。第二代默认采用独立包名和正式发布签名，与第一代并存；最终包标识在客户端初始化时固定。这样迁移不依赖跨应用读取私有目录。Windows 从旧源码目录或应用数据目录导出同一格式。原始备份文件保留，题目未匹配或版本不同的记录明确列出，完成验证后再处理旧客户端。

学习先支持本机免登录；用户选择同步时再关联账号，并支持导出、恢复和设备退出。同步契约在 N05 实现前固定，M2 验收，M3 验证三端行为：

- 每台设备有递增序号，每次学习会话内的作答有固定顺序；服务端返回统一版本和确认序号，重复事件 ID 只处理一次。
- 跨设备对同题基于同一旧状态的作答视为并发批次，全部保留原记录；该批次对连续正确计数最多贡献一次，有错答则重新学习，避免把两台设备的同时答对当作两次巩固。
- 并发批次只生成一次调度更新，取该批次中较低的掌握结果；保存原始时间、服务端接收时间及调度采用的有效时间。正常离线会话按本地顺序回放，异常时间和负间隔进入校正流程，校正过程可追踪。
- 章节或全局重置生成新的学习代次。旧代次设备随后上传的作答保存为历史，不能恢复已重置的进度；设备取得新代次后继续学习。
- 账号切换时，本机匿名记录与各账号分开；导入、关联或退出都保留明确归属。重置、时钟偏差、并发和恢复通过固定事件序列测试，再接入真实双设备走查。

### M3：分发、同步与维护做到可持续

安装包通过 Releases 分发，主页同时提供 Web 使用入口与平台下载；客户端有版本号、更新说明和数据备份入口。发布流程自动检查附件存在、摘要与链接，解决此次安装包失联暴露的维护问题。

学习事件使用设备生成的唯一 ID 去重。离线操作进入待同步队列，恢复网络后提交；服务端保存事件并生成进度视图。两台设备对同一题作答、设备时间偏差、重复上传、退出账号后本地记录归属，都有明确规则和回归用例。

客户端 TypeScript 负责即时判分，服务端按同一题目版本和呈现选项复核计分。两端实现使用同一套输入/预期结果样例，覆盖多选部分得分、选项变式、短卷和重复提交。调度模型与参数版本随学习事件保存。

编辑资料采用版本检查与冲突提示；原始文件独立保存。账号区分学习者、资料编辑者和管理员；公开内容与团队工作区分别授权，模型服务凭据只在服务端使用。离线包按专题下载，显示体积和版本，支持清理文件而保留学习记录。备份包含数据库与对应文件清单，并实际做一次恢复。收费服务、域名与运行环境在部署时确定；本地开发和可替换的接口先完成。

### M4：把“怎么读”做成可以学习的产品

字库提供汉字、音标、Unicode、女书输入与字形候选查询。每张字卡有代表字形、音标与已有声音、对应表达、异体对照、实际例句、人物角色和文献位置。可点击来源、切换不同释读，也可保存自己的疑问。

课程由材料生长：从一个字的辨认，到词句中的使用，再到读懂短篇。练习包括听音选字、同字异形匹配、句中辨义、看图找字、读句回忆。手写练习保存笔迹和参考叠图，先反馈可观察的形态差异，再评估自动评分的必要性。

录音界面提供逐句循环、速度调整、原页定位、跟读回放。同一句话的不同传承人录音可对照聆听。合成语音作为研究和辅助练习单独评估，来源明确的真实录音承担原声学习。

### M5：《合集》与其他文献的 AI 整理

先定位电子文件、登记卷册，检查是否已有文字层、汉字对照、目录和索引。按不同版面与材料质量选取代表页，形成小型校订基准，再开始批处理。

处理管线：

```text
原件登记 → 页码/版面定位 → 行与字例定位
                       ↘ 中文释文与目录提取
字形候选识别 + 对照文本匹配 → 对齐候选 → 人工集中校订
                                          ↓
                         字库 / 阅读器 / 检索 / 学习素材
```

识别采用分工：版面与中文文本交给相应 OCR；女书先比较旧模型、图像检索及视觉模型的候选结果；语言模型结合已有释文做对齐和提示。识别结果保存候选、位置和版本，校订者可接受、改判或暂存难字。

标注工具优先实现键盘快速操作、同形聚类、相似字并排、批量接受共同判定、一次更正联动相关候选、原文定位及撤销。主动学习将模型分歧、少见字形和新书写者样本送到复核队列，逐步减少重复劳动。

评测以原图/作品/书写者隔离的留出集进行：记录字形候选 Top-1/Top-5、行切分与对齐错误、原文定位正确性，以及校订一分钟能处理多少内容。候选识别不佳时先交付字形检索和对齐辅助；新增样本后再训练，不让整页 OCR 成为所有功能的前置条件。

任务按页或作品分批，保存输入摘要与检查点。失败重试只重算受影响部分；模型更换保留旧输出，便于比较。以试点实测的每页时间、复核比例、费用和存储增量，估算全书处理规模。

### M6：让研究者能提出问题、回到材料

研究工作区支持人物、地点、作品和议题检索。搜索结果首先给出原文片段与位置，可加入专题、并排比较、添加注释，并导出引用或资料包。

问答检索覆盖文字、页区和音频片段；答案中的具体判断链接到具体材料。不同来源的观点可以并列呈现，点开即可看到上下文。检索、资料引用和回答分别评估，用真实研究问题检查“有没有找全、引用是否支持表述、是否遗漏相反材料”。

团队可以共建专题、分配校订、讨论字例、发布经整理的学习包。学习侧提供小组测验和共同薄弱点，帮助下一次讨论安排内容。

田野工具箱包括离线记录、录音与照片关联、访谈转写与说话人校订、人物/地点登记、每日材料归档、主题编码及带引用的报告草稿。材料访问范围由资料设置控制，公开展览只取指定内容。

### M7：从材料组织出可以传播的作品

先完成一个有真实人物、手稿与声音的专题，再扩展专题系列。数字展览支持原页细看、字形互动、音频、人物时间线、地图与观点比较；需要空间体验的题材再制作三维场景。

声音专题可以围绕同一首歌的不同版本组织；视频专题从长访谈中生成候选片段、字幕和章节，保留通向原始录音/视频的定位。

多语言以已校订中文内容、术语表与原始引用为基础，逐条管理译文版本。创作工坊支持用户选取有依据的表达与字形，排成书签、贺卡、诗文页并导出；输入汉语时先提供可查证的表达候选与语境。

文化地图连接地点、人物、作品和学习任务，可下载研学资料包用于实地访问。课程预约、合作创作和社区投稿在实际参与者及运营安排明确后接入。投稿、校订和作品展示共用资料版本机制。

| 离线与同步可信 | 断网、重启、重复上传、两设备交错、升级和恢复的完整过程 | 保留事件、重算视图，定位丢失或冲突点 |

| 阅读与声音自然联动 | 手机触摸与电脑操作，句子定位、播放/暂停、循环和后台返回 | 优先修对齐和交互，按设备处理差异 |

性能先记录基准：移动设备首次可用时间、离线打开、长页滚动、字库检索与音频响应；目标随代表设备的实测确定。OCR 工期由样本吞吐估算，持续记录处理与复核耗时，避免以生成页数替代完成质量。

关键阶段请独立审视者只看用户目标、实际产物和测试证据，检查是否遗漏文字学习、是否把材料压成固定答案、是否出现接口无法集成。评审意见必须落实为修改或有证据的取舍。

## 11. 自主执行的范围与状态维护

在已启动的开发阶段内，Agent 自行完成依赖选择、目录调整、数据迁移脚本、可逆 UI 方案、功能实现、调试、测试和本地构建。版本锁定、接口变化与模型替换写入技术记录，原型实测推动调整。

涉及公开新的原始资料、显著费用、第三方数据处理或产品方向变化时，先准备好具体材料范围、运行样例和成本测算，再交由用户决定。代码与合成测试材料可以先完成相应能力验证。

每次交付保留：可运行入口、数据版本、已验证行为、实际未解决问题和下一动作。状态文件分别记录用户意图与当前实现选择，后者可以改变。原始文字保护与文字学习的长期目标在每次阶段验收时重新核对。

本轮交付止于恢复下载、回复 issue 和完成这份计划。下一次正式实施从 N01–N04 启动，并在同一轮推进可操作的学习/查字原型。
